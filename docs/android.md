# برنامهٔ اندروید

برنامهٔ اندروید **همان برنامهٔ وب** است، داخل یک پوستهٔ بومی (Capacitor 8). کد و رابط یکی است (فارسی/انگلیسی، RTL، همهٔ قابلیت‌ها)، فایل‌های برنامه داخل خود APK هستند، پس برنامه حتی بدون اینترنت باز می‌شود، و فقط داده‌ها از سرور شما (Worker) می‌آیند.

| | |
|---|---|
| شناسهٔ برنامه | `chat.amin.app` (نسخهٔ debug: `chat.amin.app.debug`، کنار نسخهٔ اصلی نصب می‌شود) |
| حداقل / هدف | اندروید ۷ (API 24) / API 36 |
| دسترسی‌ها | فقط `INTERNET`، `RECORD_AUDIO` (ورودی صوتی) و `MODIFY_AUDIO_SETTINGS`. هیچ‌چیز دیگر (مخاطبین، موقعیت، حافظه، …) |
| ترافیک | فقط https (متن ساده مسدود است) |
| پشتیبان‌گیری Google | **خاموش** (`allowBackup=false`)؛ توکن نشست و کلید رمزنگاری سرتاسری نباید به ابر بروند |

## وضعیت راستی‌آزمایی

- ✅ **APK روی ماشین واقعی GitHub ساخته شد** (اولین اجرا: حدود ۴ مگابایت) و ۱۰ بررسی محتوا روی آن پاس شد (پایین‌تر).
- ❌ **روی هیچ گوشی یا شبیه‌ساز اجرا نشده.** من دستگاه یا شبیه‌ساز نداشتم. پس رفتار WebView واقعی (میکروفون، کیبورد، حاشیه‌های نوار وضعیت/ناوبری، رنگ‌ها، سرعت) **تأییدنشده** است. چیدمان فقط با Chrome شبیه‌سازی‌شدهٔ موبایل آزمایش شده.
- ❌ **اعلان (Notification/Push) ساخته نشده.** پیام‌ها و یادآورها وقتی برنامه باز است (یا در پس‌زمینهٔ کوتاه) می‌رسند؛ وقتی برنامه کاملاً بسته است هیچ اعلانی نمی‌آید. این کمبود جدی یک پیام‌رسان است؛ ساختنش به یک پروژهٔ Firebase (FCM) و کلید سرور نیاز دارد که نداشتم و نمی‌شد آن را آزمایش کرد.
- ❌ انتشار در Google Play، و iOS: نه.

## گرفتن APK (بدون نصب هیچ‌چیز روی رایانه)

۱. در GitHub به مخزن بروید ← زبانهٔ **Actions** ← workflow به نام **Android app**.
۲. آخرین اجرای سبز را باز کنید؛ پایین صفحه در بخش **Artifacts**، فایل `amin-chat-debug-apk` را دانلود کنید (یک zip که APK داخلش است. ماندگاری ۳۰ روز؛ نسخهٔ امضاشده ۹۰ روز).
۳. هر تغییر در `apps/web`، `packages/shared` یا قفل وابستگی‌ها خودکار یک APK تازه می‌سازد. دستی هم می‌شود: Actions ← Android app ← **Run workflow** (با دو ورودی بالا؛ بخش بعد).

## نصب روی گوشی

۱. فایل APK را به گوشی بفرستید و باز کنید. اندروید از شما اجازهٔ «نصب از منبع ناشناس» برای همان برنامه (مرورگر یا مدیر فایل) را می‌خواهد.
۲. یا با رایانه: `adb install amin-chat-debug.apk`.
۳. **نشانی سرور:** اگر هنگام build آدرس را ندادید، در اولین صفحه (ورود/ثبت‌نام) یک خانهٔ «نشانی سرور» هست؛ آدرس Worker خودتان را بنویسید (مثلاً `https://amin-chat.example.workers.dev`). بعداً هم از تنظیمات قابل تغییر است.

### آدرس را داخل برنامه بسازید (توصیه می‌شود)

در GitHub: Settings ← Secrets and variables ← Actions ← تب **Variables** ← New repository variable:

| متغیر | مقدار | کاربرد |
|---|---|---|
| `VITE_API_BASE` | `https://chat.example.com` | آدرس اصلی؛ کاربر دیگر چیزی تایپ نمی‌کند |
| `VITE_API_BASES` | `https://relay1.example.com https://relay2.example.net` | رله‌ها؛ نصب تازه‌ای که هیچ‌وقت به سرور نرسیده هم می‌تواند به آن‌ها برود ([connectivity.md](connectivity.md)) |

(یا هنگام «Run workflow» در همان دو خانه بنویسید؛ مقدار دستی بر متغیر مخزن مقدم است.) این‌ها در جاوااسکریپت برنامه **جاسازی و عمومی** می‌شوند؛ هیچ رازی در آن‌ها نگذارید.

## امضای نسخهٔ نهایی (release)

بدون امضا فقط APK نوع debug ساخته می‌شود. **همین الان کلید بسازید**، چون:
- Android نسخهٔ تازه را فقط روی نسخهٔ قبلیِ امضاشده با **همان کلید** نصب می‌کند. بدون کلید ثابت، هر اجرای CI یک کلید debug تازه می‌سازد و APK بعدی روی قبلی نصب **نمی‌شود**؛ باید اول حذف کنید و با حذف، نشست و کلید رمزنگاری سرتاسری آن دستگاه از بین می‌رود.
- با کلید ثابت، APK نوع debug هم با همان کلید امضا می‌شود و به‌روزرسانی در جا نصب می‌شود.

```bash
keytool -genkeypair -v -keystore amin-chat-release.keystore -alias amin -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 amin-chat-release.keystore > keystore.b64          # در macOS: base64 -i amin-chat-release.keystore -o keystore.b64
```

در GitHub، Settings ← Secrets and variables ← Actions ← **Secrets** چهار مقدار بسازید:

| Secret | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای `keystore.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز Keystore |
| `ANDROID_KEY_ALIAS` | `amin` |
| `ANDROID_KEY_PASSWORD` | **همان رمز Keystore** (قالب پیش‌فرض PKCS12 دو رمز جدا را نمی‌پذیرد) |

از این به بعد هر اجرا علاوه بر debug، `amin-chat-release-apk` را هم می‌سازد. **فایل Keystore و رمزها را جای امن نگه دارید**: اگر گم شود، دیگر نمی‌توانید به‌روزرسانی‌ای منتشر کنید که روی نسخهٔ نصب‌شده بنشیند. آن را در گیت **نگذارید** (`*.keystore` در `.gitignore` است).
شمارهٔ نسخه (`versionCode`) خودکار برابر شمارهٔ اجرای workflow است و `versionName` از `apps/web/package.json` می‌آید.

## بررسی‌هایی که CI روی APK انجام می‌دهد

بعد از ساخت، `aapt2` APK را باز می‌کند و اگر هرکدام نادرست باشد workflow قرمز می‌شود (نتیجهٔ هر بررسی جدا چاپ می‌شود):

۱. شناسه `chat.amin.app.debug` و `versionCode` برابر شمارهٔ اجرا؛ ۲. حداقل Android ‏۲۴؛ ۳. هیچ دسترسی بیش از سه‌تای بالا؛ ۴. `RECORD_AUDIO` هست؛ ۵. `allowBackup=false`؛ ۶. `usesCleartextTraffic=false`؛ ۷–۸. `index.html` و اسکریپت اصلی داخل APK هستند؛ ۹. Capacitor با https سرو می‌کند؛ ۱۰. اگر `VITE_API_BASE` داده شده، آدرس واقعاً داخل اسکریپت جاسازی شده.

منطق این بررسی‌ها هم آزمایش شد: با خروجی ساختگیِ `aapt2` در هر دو قالب (قدیمی و جدید) و با حالت‌های خراب (دسترسی اضافه، پشتیبان‌گیری روشن، حداقل نسخهٔ اشتباه).

## ساخت محلی (اختیاری)

نیاز: JDK ‏21 و Android SDK (پلتفرم 36 و build-tools)، Node 22.

```bash
npm ci
npm run build -w @aminchat/web
cd apps/web && npx cap sync android          # فایل‌های وب را داخل پروژهٔ اندروید می‌کند
cd android && ./gradlew assembleDebug        # خروجی: app/build/outputs/apk/debug/
```

برای `VITE_API_BASE` همان متغیر را پیش از `npm run build` در محیط بگذارید. پوشهٔ `apps/web/android/app/src/main/assets/public` و `capacitor.config.json` تولیدی‌اند و در گیت نمی‌روند.

## چیزهایی که باید بدانید

- **ورود دوباره پس از نصب مجدد.** چون پشتیبان‌گیری خاموش است، حذف و نصب دوبارهٔ برنامه یا گوشی تازه یعنی ورود دوباره. **کلید خصوصی چت‌های رمزنگاری سرتاسری (E2EE)** هم فقط روی همان دستگاه است ([SECURITY.md](SECURITY.md)): با نصب مجدد، تاریخچهٔ آن چت‌ها خوانا نمی‌ماند. این طراحی عمدی است، نه نقص.
- **میکروفون.** ورودی صوتی از `getUserMedia` در WebView استفاده می‌کند و اندروید یک بار اجازه می‌پرسد. Capacitor این درخواست را به دسترسی `RECORD_AUDIO` وصل می‌کند؛ آزمایش روی دستگاه واقعی نشده.
- **رابط داخل APK ثابت است.** برخلاف نسخهٔ وب (که با هر deploy عوض می‌شود)، گوشی تا وقتی APK تازه نصب نکند همان رابط قدیمی را دارد. API نسخه‌بندی یا بررسی سازگاری ندارد؛ پس بعد از هر تغییر ناسازگار در API (مثلاً تغییر نام یک فیلد)، APK تازه هم بسازید و به کاربران بدهید، وگرنه نسخهٔ قدیمی خراب می‌شود.
- **Service Worker** داخل اندروید ثبت نمی‌شود (فایل‌ها از خود APK خوانده می‌شوند).
