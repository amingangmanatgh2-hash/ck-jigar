# راه‌اندازی روی Cloudflare

یک Worker همه‌چیز را سرو می‌کند: برنامهٔ وب (فایل‌های ثابت)، API (`/api/*`)، سه Durable Object، کار زمان‌بندی‌شدهٔ هر دقیقه، و اتصال به Workers AI، D1 و R2 (و Groq، اگر کلیدش را بدهید).
بدون سرور دیگر، بدون Docker. دو راه برای deploy هست و هر دو یک فرمان را اجرا می‌کنند (`npm run deploy`):

| راه | برای چه کسی | چه می‌خواهد |
|---|---|---|
| **الف) GitHub Actions** (بدون ترمینال) | اگر فقط مرورگر دارید | یک Secret در GitHub (با اطلاعات حساب Cloudflare و، اگر خواستید، کلید Groq)، یک بار کلیک روی «Run workflow» |
| **ب) از رایانهٔ خودتان** | اگر Node.js دارید | `npx wrangler login` و `npm run deploy` |

> **راستی‌آزمایی:** همهٔ منطق برنامه با آزمون خودکار و Worker محلی (workerd) آزمایش شده، ولی **من به حساب Cloudflare دسترسی نداشتم**؛ پس هیچ‌کدام از مراحل زیر روی Cloudflare واقعی اجرا نشده‌اند و هیچ فراخوانی واقعی به Workers AI یا Groq هم انجام نشده است (سرور Groq هم در آزمون‌ها ساختگی است و بر پایهٔ مستندات رسمی نوشته شده).
> چیزهایی که **خوانده و آزمایش شده‌اند**: منطق ترتیب مراحل، بررسی نام مدیر و ذخیرهٔ کلید Groq (۳۵ آزمون)، پیش‌آزمون Cloudflare/Groq با پاسخ‌های ساختگی (۲۰ آزمون)، اجرای `npm run deploy` با wrangler واقعی که بدون اتصال امن شکست می‌خورد و هیچ‌چیز نمی‌سازد، و رفتار ساخت منابع در **کد منبع** wrangler همین نسخه (۴٫۱۶۲٫۰).
> چیزی که **اجرا نشده**: خودِ ساخت D1/R2 و انتشار روی Cloudflare. بعد از deploy بخش «[بررسی](#بررسی-پس-از-راه‌اندازی)» را حتماً انجام دهید.

## پیش‌نیازها (برای هر دو راه)

| | |
|---|---|
| حساب Cloudflare | رایگان کافی است. روش پرداخت فقط برای **R2** لازم است (ردیف بعد)، و R2 اختیاری است |
| پلن Workers | **روی پلن رایگان هم امتحان می‌شود، با دو محدودیت؛ Workers Paid (۵ دلار در ماه) امن‌تر است.** پلن رایگان فقط **۱۰ میلی‌ثانیه CPU برای هر درخواست** می‌دهد. **(۱) ورود و ثبت‌نام:** هش‌کردن رمز با ۱۰۰٬۰۰۰ دور PBKDF2 حدود ۲۰ میلی‌ثانیه CPU می‌گیرد (اندازه‌گیری من روی یک CPU معمولی؛ گزارش پروژه‌های دیگر هم همین را نشان می‌دهد: خطای ۱۱۰۲ روی هر ورود). برای همین در `wrangler.jsonc` مقدار `PASSWORD_HASH_ITERATIONS` روی `20000` است (حدود ۴ میلی‌ثانیه). این رمزها را در برابر سرقت پایگاه داده ضعیف‌تر نگه می‌دارد؛ جزئیات در [SECURITY.md](SECURITY.md). **(۲) پاسخ‌های بلند هوش مصنوعی:** کل یک پاسخ داخل یک فراخوانی Durable Object اجرا می‌شود و برای پخش زنده تقریباً هر ۱۵۰ میلی‌ثانیه یک پیام می‌فرستد؛ احتمال دارد روی پلن رایگان یک پاسخ بلند به سقف ۱۰ میلی‌ثانیه برسد و نیمه‌کاره قطع شود. این را نتوانستم اندازه بگیرم و **تأییدنشده** است. اگر دیدید، به Workers Paid بروید (بدون هیچ تغییر کد؛ فقط `PASSWORD_HASH_ITERATIONS` را هم `100000` کنید): داشبورد ← Workers & Pages ← Plans ← Upgrade ([لینک مستقیم](https://dash.cloudflare.com/?to=/:account/workers/plans)) |
| **R2** (ذخیرهٔ فایل؛ اختیاری) | **لازم نیست.** اگر R2 در حساب روشن نباشد، پیش‌آزمون «R2 file storage» را هشدار می‌دهد و سرویس **بدون ذخیرهٔ فایل** بالا می‌آید: گفتگو، هوش مصنوعی، عامل‌ها، حافظه، کارها و تبدیل صدا به متن کار می‌کنند؛ **فقط ارسال فایل و عکس خاموش است** و برنامه همین را می‌گوید (دکمهٔ پیوست غیرفعال با توضیح). هر وقت خواستید: داشبورد ← Storage & databases ← R2 ← Overview ← مراحل خرید ([لینک مستقیم](https://dash.cloudflare.com/?to=/:account/r2/overview)؛ Cloudflare روش پرداخت می‌خواهد، ولی تا ۱۰ گیگابایت در ماه رایگان است) و دوباره deploy کنید؛ خودش متوجه می‌شود و سطل را اضافه می‌کند. خطای **دسترسی** R2 (نه «روشن نیست») همچنان متوقف می‌کند، چون با یک ردیف توکن درست می‌شود |
| نشانی `workers.dev` | **خودکار.** حساب تازه نشانی ندارد و Wrangler داخل GitHub نمی‌تواند از شما بپرسد، پس مرحلهٔ «Prepare the account» درست قبل از انتشار یک نشانی رایگان ثبت می‌کند (اول نام کاربری مدیر، مثلاً `amin-ck`؛ اگر گرفته بود نام بعدی) و در پیام اجرا می‌گوید کدام را گرفت. اسم دلخواه می‌خواهید؟ **قبل از اجرا** یک بار داشبورد ← Workers & Pages را باز کنید و خودتان انتخاب کنید ([لینک مستقیم](https://dash.cloudflare.com/?to=/:account/workers/onboarding)). نشانی‌ای که از قبل هست **هرگز** عوض نمی‌شود. بعداً هم از داشبورد ← Workers & Pages ← Account details ← Change قابل تغییر است |
| نام مدیر | در `apps/api/wrangler.jsonc` مقدار `ADMIN_USERNAMES` را **نام کاربری دلخواه خودتان** بگذارید (بخش «تنظیمات» پایین). نام باید با حرف انگلیسی شروع شود، ۳ تا ۳۲ حرف انگلیسی، عدد یا `_` باشد و رزرو نباشد (`admin`، `administrator`، `root`، `system`، `support`، `moderator`، `ai`، `bot`، `aminai`، `amin_ai`، `amin-ai`، `aminchat`، `amin_chat`)؛ نامی که کسی نتواند ثبت کند، deploy را با پیام روشن متوقف می‌کند. در همین مخزن از پیش `amin_ck` گذاشته شده؛ نام دیگری می‌خواهید؟ همان خط را عوض کنید. **بلافاصله بعد از deploy با همان نام ثبت‌نام کنید**؛ هر کس زودتر با آن نام ثبت‌نام کند مدیر می‌شود (اگر مخزن عمومی است، این نام و آدرس سرویس برای همه دیدنی است؛ پس معطل نکنید) |

هزینهٔ Workers AI: ۱۰٬۰۰۰ نورون در روز **رایگان** است و بعد از آن ۰٫۰۱۱ دلار برای هر هزار نورون. برای اینکه یک کاربر نتواند هزینه بسازد، هر کاربر سهمیهٔ خودش را دارد (پیش‌فرض: ۳۰۰٬۰۰۰ توکن در روز، ۴۰۰ درخواست در روز، ۴٬۰۰۰٬۰۰۰ توکن در ماه؛ قابل تغییر با `DEFAULT_*` یا برای هر کاربر با `PUT /api/admin/users/:id/quota`). بعضی مدل‌های Workers AI به پلن پولی یا اعتبار AI Gateway نیاز دارند؛ مدلی که دسترس‌پذیر نباشد در برنامه «آمادهٔ استفاده» نشان داده **نمی‌شود**.

## Groq: سرویس هوش مصنوعی دوم (اختیاری)

Workers AI همچنان زیرساخت اصلی است. Groq سرویس دوم و رایگان (با سقف) است که چهار کار می‌کند:

- **کارهای سریع و کوتاه را اول جواب می‌دهد:** مسیریابی بین عامل‌ها، برنامه‌ریزی کارها، عنوان گفتگوها، خلاصه‌ها، و «عامل سریع» (مثلاً «چت امین را باز کن»: فقط پیدا می‌کند و دکمه‌ای می‌دهد؛ چیزی نمی‌فرستد).
- **گفتگو، کد و تصویر** اول به Workers AI می‌روند؛ Groq پشتیبان آن‌هاست (تصویر و صدا هرگز به Groq نمی‌روند).
- **پشتیبان‌گیری دوطرفه:** اگر سهمیهٔ رایگان روزانهٔ Workers AI تمام شود یا مدلی شلوغ باشد، دستیار با Groq جواب می‌دهد؛ اگر Groq شلوغ باشد با Workers AI. هرچه سرویس بیشتر، پشتیبان بیشتر.
- **صادق است:** بدون کلید، مدل‌های Groq در صفحهٔ «مدل‌ها و مصرف» «متصل نیست» نشان داده می‌شوند و هرگز «آماده» نمی‌شوند. مدل فقط وقتی «آماده» است که یک فراخوانی کوچک واقعی به آن موفق شده باشد.

**چطور:** [console.groq.com](https://console.groq.com) ← API Keys ← Create API Key (کلید با `gsk_` شروع می‌شود، فقط یک بار نمایش داده می‌شود). در GitHub یک Secret به نام `GROQ_API_KEY` بسازید. deploy آن را **بعد از ساخته‌شدن Worker** روی خود Worker ذخیره می‌کند (`wrangler secret put`؛ مقدار فقط از ورودی استاندارد می‌رود، نه خط فرمان، نه فایل، و هرگز چاپ نمی‌شود). فاصله یا خط جدیدِ اضافه دور کلید حذف می‌شود؛ کلیدی که وسطش فاصله یا نقل‌قول دارد ذخیره نمی‌شود و هشدار می‌دهد.

- **عوض‌کردن کلید:** Secret گیت‌هاب را عوض کنید و دوباره deploy را اجرا کنید.
- **بدون Secret در گیت‌هاب:** چیزی دست نمی‌خورد؛ کلیدی که قبلاً روی Cloudflare گذاشته‌اید می‌ماند. (از رایانه: `cd apps/api && npx wrangler secret put GROQ_API_KEY`.)
- **خاموش‌کردن Groq:** `cd apps/api && npx wrangler secret delete GROQ_API_KEY` و Secret گیت‌هاب را هم پاک کنید (وگرنه deploy بعدی دوباره می‌گذارد).
- شکست ذخیرهٔ کلید، deploy را شکست‌خورده نمی‌کند (Worker بالاست و با Workers AI کار می‌کند)؛ یک هشدار با دلیل روی صفحهٔ اجرا می‌آید.

**حریم خصوصی (مهم):** آنچه به یک مدل Groq فرستاده شود (پیام کاربر، و برای کارهای سریع بخش‌هایی از گفتگو یا نتیجهٔ ابزارها) **در Groq و بیرون از Cloudflare پردازش می‌شود**، طبق شرایط Groq. در گفتگوهای سرّی (E2EE) فقط متنی که خود کاربر انتخاب و ارسال کرده به مدل می‌رسد و این مدل می‌تواند Groq باشد. اگر نمی‌خواهید، کلید را نگذارید. دسترسی هر گفتگو به AI مثل قبل مستقل است.

**سقف‌ها:** سقف رایگان Groq برای **کل حساب Groq** است، نه برای هر کاربر؛ یعنی همهٔ کاربران این سرویس یک سقف را شریک‌اند (مقدار پایه در مستندات Groq: ۳۰ درخواست در دقیقه و ۸٬۰۰۰ توکن در دقیقه برای هر مدل؛ سقف واقعی کلید شما در console.groq.com/settings/limits است و من آن را ندیده‌ام). برای همین: درخواست‌های بزرگ‌تر از حدود ۵٬۰۰۰ توکن اصلاً به Groq فرستاده نمی‌شوند (متغیر `GROQ_MAX_INPUT_TOKENS`؛ با پلن پولی بالاتر ببرید)، و وقتی Groq بگوید «شلوغ است» (۴۲۹) همان مدل تا زمانی که Groq گفته کنار گذاشته می‌شود و Workers AI ادامه می‌دهد. سهمیهٔ هر کاربر (توکن در روز) برای هر دو سرویس یکی است.

## راه الف: GitHub Actions (بدون ترمینال)

۱. **دکمهٔ «Run workflow» فقط برای workflowهایی که در شاخهٔ پیش‌فرض (`Main`) هستند ظاهر می‌شود.** پس یا اول Pull Request را Merge کنید، یا بدون Merge از «[فایل `deploy/REQUEST`](#بدون-merge-و-بدون-هیچ-دکمه‌ای-فایل-deployrequest)» (پایین‌تر در همین بخش) استفاده کنید.

۲. **شناسهٔ حساب:** داشبورد Cloudflare ← Workers & Pages ← بخش «Account Details» ← دکمهٔ کپی کنار «Account ID». (یا Ctrl+K را بزنید و Copy account ID را تایپ کنید.)

۳. **توکن API:** [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens) ← Create Token ← قالب **Edit Cloudflare Workers** ← Use template. این قالب (طبق فهرست رسمی Cloudflare) ردیف‌های Workers Scripts، Workers R2 Storage و Account Settings را دارد ولی **D1 را ندارد**؛ پس یک ردیف دیگر اضافه کنید (دکمهٔ «+ Add more»): Account ← **D1** ← **Edit**. در «Account Resources» همان حساب خودتان را انتخاب کنید ← Continue to summary ← Create Token. مقدار توکن **فقط یک بار** نشان داده می‌شود؛ همان لحظه کپی کنید.

   **این چهار ردیف باید در توکن باشد، هر چهار از نوع Account** (اگر توکن را «Custom» ساخته‌اید، دقیقاً همین‌ها؛ ردیف Zone لازم نیست و دامنه هم لازم نیست):

   | ردیف | سطح | برای چه |
   |---|---|---|
   | Workers Scripts | **Edit** | بارگذاری Worker، فایل‌های وب، زمان‌بندی، Secretها. **Workers Tail** جای آن نیست؛ آن فقط فهرست را می‌خواند و بارگذاری نمی‌کند |
   | D1 | **Edit** | ساختن پایگاه داده و اجرای migrationها |
   | Workers R2 Storage | **Edit** | ساختن و خواندن مخزن فایل `amin-chat-files` |
   | Account Settings | **Read** | خواندن اطلاعات حساب (مثلاً آدرس workers.dev) |

   **توکن را قبلاً ساخته‌اید و اجرا می‌گوید «Authentication error»؟** نیازی به توکن تازه نیست: [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens) ← توکن خودتان ← **Edit** ← با «+ Add more» ردیف‌های کم را اضافه کنید ← Continue to summary ← Update Token. **متن توکن عوض نمی‌شود**، پس Secret در GitHub همان می‌ماند. اجرا خودش فهرست همین ردیف‌ها را در یک هشدار به نام «Preflight: Token rights» می‌دهد.

۴. **اطلاعات حساب را به GitHub بدهید (ساده‌ترین راه: فقط یک Secret).** [این لینک](https://github.com/amingangmanatgh2-hash/ck-jigar/settings/secrets/actions/new) را باز کنید (یا: مخزن ← Settings ← Secrets and variables ← Actions ← New repository secret). دو خانه دارد:
   - **Name:** `DEPLOY_ENV`
   - **Secret:** همان خط‌هایی که در چت می‌نویسید، هر کدام در یک خط (بدون فاصلهٔ اضافه، بدون نقل‌قول). مثال با مقدارهای ساختگی:

   ```
   CF_ACCOUNT_ID=0123456789abcdef0123456789abcdef
   CF_API_TOKEN=cfut_توکن-خودتان
   GROQ_API_KEY=gsk_کلید-خودتان
   ```

   خط Groq اختیاری است. اسم‌ها را `CLOUDFLARE_ACCOUNT_ID` و `CLOUDFLARE_API_TOKEN` هم می‌شود نوشت؛ بزرگی و کوچکی حروف مهم نیست، `export `، نقل‌قول، `:` به‌جای `=` و خط‌های توضیح (`#`) را هم می‌پذیرد. خطی که به شکل `اسم=مقدار` نباشد رد می‌شود و **متنش هرگز در لاگ نمی‌آید**؛ مقدار توکن‌ها پیش از هر کاری در لاگ پوشانده می‌شود. توکن را هرگز در خود مخزن یا چت عمومی ننویسید.

   **راه دوم، به‌جای آن:** سه Secret جدا با همین اسم‌ها: `CLOUDFLARE_ACCOUNT_ID`، `CLOUDFLARE_API_TOKEN` و (اختیاری) `GROQ_API_KEY` (اسم‌های کوتاه‌تر `CF_ACCOUNT_ID` و `CF_API_TOKEN` هم پذیرفته می‌شوند). اگر هر دو راه باشد، Secretِ جدا برنده است.

   باید از نوع **Repository secret** باشد؛ «Variables»، «Codespaces» و «Dependabot» جداست و workflow آن‌ها را نمی‌بیند. اگر چیزی به workflow نرسد، اجرا در پیش‌آزمون می‌ایستد و برای هر اسمِ محتمل در Summary و در یک هشدار می‌نویسد «هست» یا «نیست» (فقط بله/خیر؛ هرگز مقدار)؛ از روی همان معلوم می‌شود جای دیگری گذاشته‌اید یا اسم را اشتباه نوشته‌اید. (مورد سوم، `GROQ_API_KEY`، اختیاری است: [بخش Groq](#groq-سرویس-هوش-مصنوعی-دوم-اختیاری) پایین.)

۵. فایل `apps/api/wrangler.jsonc` را در GitHub باز کنید (آیکن مداد) و خطِ `"ADMIN_USERNAMES": ""` را پیدا کنید؛ نام را **بین دو نقل‌قولِ خالی** بگذارید، مثلاً `"ADMIN_USERNAMES": "my_boss_2027"` (حروف انگلیسی، عدد و `_`؛ رزروها مجاز نیستند) و Commit کنید.

۶. Actions ← **Deploy to Cloudflare** ← Run workflow. حدود ۵ تا ۸ دقیقه طول می‌کشد. اول **پیش‌آزمون (Preflight)**: از Cloudflare می‌پرسد توکن، Workers، D1 و R2 درست‌اند، و (اگر گذاشته‌اید) از Groq می‌پرسد کلید کار می‌کند، و **همهٔ مشکلات را یک‌جا** می‌نویسد، هر مشکل یک «error» جدا با راه‌حلش (مثلاً «به توکن Account ← D1 ← Edit را اضافه کنید»)، بدون چاپ هیچ Secret. بعد آزمون‌ها؛ بعد «Prepare the account» (اگر حساب نشانی workers.dev ندارد، یکی رایگان ثبت می‌کند)؛ بعد ساخت و deploy. اگر پیش‌آزمون یا آزمونی شکست بخورد **چیزی منتشر نمی‌شود**. سه چیز فقط **هشدار** است و جلوی deploy را نمی‌گیرد: مشکل Groq، نبودن نشانی workers.dev (خودکار ثبت می‌شود)، و **روشن‌نبودن R2** (سرویس بدون ذخیرهٔ فایل بالا می‌آید و در صفحهٔ همان اجرا با پیام «File storage is OFF» می‌گوید).

۷. در **صفحهٔ همان اجرا** (بالای صفحه، بخش Summary) نوشته می‌شود: «AMIN CHAT is live: https://amin-chat.‹زیردامنهٔ-شما›.workers.dev». همان آدرس شماست. workflow خودش هم `/api/health` را تا چند دقیقه می‌آزماید.

### بدون Merge و بدون هیچ دکمه‌ای: فایل `deploy/REQUEST`

اگر Pull Request را Merge نمی‌کنید، دکمهٔ «Run workflow» هرگز ظاهر نمی‌شود، ولی لازم هم نیست. هر commit که فایل `deploy/REQUEST` را روی شاخهٔ `Main` یا روی شاخه‌ای که با `arena/` شروع می‌شود تغییر بدهد، همان workflow را شروع می‌کند. **خط اول** فایل:

- `check`: فقط طرح و آزمون‌ها اجرا می‌شوند. هیچ Secret خوانده و هیچ چیز منتشر نمی‌شود (برای اطمینان از سالم‌بودن مسیر).
- `deploy`: منتشر می‌کند؛ به Secretِ مرحلهٔ ۴ نیاز دارد (`DEPLOY_ENV`، یا سه Secret جدا). اول پیش‌آزمون اجرا می‌شود؛ اگر Secretی نباشد یا چیزی کم باشد، **همهٔ کمبودها یک‌جا** به‌صورت «error» نوشته می‌شود و هیچ‌چیز منتشر نمی‌شود.
- **اگر اجرا به‌خاطر نبودن Secret شکست خورد:** Secretها را بگذارید و در صفحهٔ **همان اجرا** دکمهٔ «Re-run all jobs» را بزنید. لازم نیست چیزی commit کنید؛ اجرای دوباره از Secretهای تازه می‌خواند.

خط‌های بعدی یادداشت آزادند؛ برای شروع یک اجرای تازه چیزی در فایل عوض کنید. نتیجه روی صفحهٔ همان اجرا می‌آید: آدرس سایت به‌صورت یک «notice» و در Summary، و هر خطا به‌صورت «error» با خطوط مهمِ آن.

اولین اجرا پایگاه داده (`amin-chat-db`) و سطل فایل (`amin-chat-files`) را می‌سازد؛ Wrangler آن‌ها را **با نام** پیدا می‌کند، پس اجرای دوباره یا وجود قبلی‌شان چیزی را دوبار نمی‌سازد. از اجرای دوم به بعد، مهاجرت‌ها **قبل** از کد جدید اجرا می‌شوند.

## راه ب: از رایانهٔ خودتان

```bash
git clone https://github.com/amingangmanatgh2-hash/ck-jigar.git && cd ck-jigar
git checkout Main                 # بعد از Merge؛ تا آن موقع: شاخهٔ arena/4651dc1b-ck-jigar
npm ci
npx wrangler login                # مرورگر باز می‌شود؛ یا CLOUDFLARE_API_TOKEN و CLOUDFLARE_ACCOUNT_ID را در محیط بگذارید
npm run preflight                 # (اختیاری) می‌پرسد توکن، Workers، D1، R2 و کلید Groq درست‌اند؛ هیچ‌چیز نمی‌سازد
GROQ_API_KEY=gsk_... npm run deploy   # کلید Groq اختیاری است؛ بدون آن فقط Workers AI
npm run deploy -- --dry-run       # فقط برنامه را چاپ می‌کند، به Cloudflare وصل نمی‌شود
npm run deploy -- --no-r2         # بدون سطل فایل (وقتی R2 در حساب روشن نیست)؛ ارسال فایل و عکس خاموش می‌ماند
npm run prepare:account           # (اختیاری) اگر حساب نشانی workers.dev ندارد، یکی رایگان ثبت می‌کند
```

`npm run deploy` این کارها را به ترتیب می‌کند و هر مرحله‌ای که شکست بخورد، بعدی‌ها اجرا **نمی‌شوند**:

1. از Cloudflare می‌پرسد پایگاه داده `amin-chat-db` هست یا نه (`wrangler d1 list`). اگر نتواند بپرسد (توکن غلط، نبودن اینترنت) **هیچ‌چیز نمی‌سازد و منتشر نمی‌کند** و می‌گوید چه چیزی را بررسی کنید.
2. برنامهٔ وب را می‌سازد.
3. **اولین بار** (پایگاه داده نیست): اول `wrangler deploy` (Wrangler پایگاه داده و سطل فایل را می‌سازد)، بعد مهاجرت‌ها. با `--no-r2` (یا `AMIN_R2=off`، که workflow وقتی پیش‌آزمون R2 را روشن‌نشده ببیند خودش می‌گذارد) فقط `wrangler deploy` از یک نسخهٔ ساخته‌شده از تنظیمات استفاده می‌کند که ردیف `r2_buckets` ندارد (`apps/api/wrangler.no-r2.generated.jsonc`، هرگز commit نمی‌شود)؛ فایل واقعی `wrangler.jsonc` دست نمی‌خورد و deploy بعدیِ با R2 روشن، سطل را اضافه می‌کند.
   **دفعه‌های بعد:** اول مهاجرت‌های D1 (`0001_init`، `0002_file_tiers`، `0003_client_ids`)، بعد `wrangler deploy`؛ تا کد جدید هیچ‌وقت با schema قدیمی روبه‌رو نشود.

۴. اگر `GROQ_API_KEY` در محیط باشد، **آخر از همه** (Worker حالا وجود دارد) آن را با `wrangler secret put` روی Worker می‌گذارد. شکست این مرحله deploy را شکست‌خورده نمی‌کند؛ هشدار می‌دهد.

آدرس چاپ‌شده مثل `https://amin-chat.<شما>.workers.dev` است.

> ذخیره‌کردن `database_id` در `wrangler.jsonc` **لازم نیست**. (من در منبع wrangler ۴٫۱۶۲٫۰ دیدم که D1 را بدون شناسه هم با نام پیدا می‌کند، چه برای `deploy` و چه برای `d1 migrations apply --remote`. در CI هم شناسه‌ها را به فایل برنمی‌گرداند و لازم هم نیست.)

| `FILES_OFFLOAD_*`، `R2_SOFT_LIMIT_BYTES`، `DRIVE_FOLDER_NAME` | [storage-drive.md](storage-drive.md) |

## Secretهای اختیاری (یک بار، روی خود Cloudflare)

```bash
cd apps/api
npx wrangler secret put RELAY_SECRET            # فقط اگر رله دارید
npx wrangler secret put SEARCH_PROVIDER         # brave یا tavily: جستجوی وب برای دستیار پژوهشگر
npx wrangler secret put SEARCH_API_KEY
npx wrangler secret put GROQ_API_KEY            # Groq: سرویس دوم هوش مصنوعی (بخش Groq بالا)
# Google Drive (فایل‌های قدیمی را به Drive می‌برد): docs/storage-drive.md
```

بدون `SEARCH_*`، دستیار پژوهشگر صادقانه می‌گوید جستجوی وب وصل نیست و منبع جعل نمی‌کند. این Secretها از GitHub لمس نمی‌شوند و با هر deploy می‌مانند (تنها استثنا `GROQ_API_KEY` است: اگر Secret گیت‌هاب با همین نام باشد، deploy آن را هر بار روی Worker می‌گذارد). Secret را بعد از اولین deploy بگذارید (پیش از آن Worker وجود ندارد).

(دامنه باید در همان حساب Cloudflare باشد.) سپس همان آدرس را در ورودی `smoke_url` workflow بدهید تا آزموده شود. توجه: گزارش‌ها می‌گویند در بعضی اپراتورهای ایران هم `workers.dev` و هم دامنهٔ شخصی روی Cloudflare کند یا قطع‌اند؛ [connectivity.md](connectivity.md) را ببینید.

## بررسی پس از راه‌اندازی

۱. `curl https://آدرس-شما/api/health` ← باید `{"ok":true,"service":"amin-chat",…,"ai":{"workers-ai":true,"groq":true}}` بدهد. بخش `ai` فقط **بله/خیر** است: کدام سرویس هوش مصنوعی کلید یا اتصال دارد (هیچ مقداری نمی‌دهد). همین جدول در Summary اجرای workflow هم هست.
۲. در مرورگر آدرس را باز کنید و با **همان نام کاربری `ADMIN_USERNAMES`** ثبت‌نام کنید. مخاطب «AMIN AI» با تیک تأیید خودکار در فهرست گفتگوها هست.
۳. **اتصال واقعی Workers AI و Groq:** منوی «مدل‌ها و مصرف» ← دکمهٔ «بررسی دسترس‌پذیری» (فقط مدیر؛ هر مدل را با یک فراخوانی کوچک واقعی می‌سنجد). برای هر سرویس یک نوار وضعیت هست؛ مدل Groq فقط وقتی «آماده» است که فراخوانی‌اش جواب داده باشد. یا از رایانهٔ خودتان:
   ```bash
   CLOUDFLARE_ACCOUNT_ID=... CLOUDFLARE_API_TOKEN=... npm run verify:ai
   ```
   (توکن باید **هر دو** دسترسی «Workers AI: Read» و «Workers AI: Edit» را داشته باشد (طبق راهنمای REST API رسمی Cloudflare). اگر توکن deploy را قبلاً ساخته‌اید، در صفحهٔ توکن‌ها آن را Edit کنید و این دو ردیف را اضافه کنید؛ مقدار توکن عوض نمی‌شود. این بررسی چند نورون از سهمیهٔ رایگان مصرف می‌شود. همین کار از GitHub Actions هم در دسترس است: workflow «Verify Workers AI».) این اسکریپت **همهٔ مدل‌ها را با همان پارامترهایی که برنامه می‌فرستد** صدا می‌زند. در محیط ساخت این کار ممکن نبود، پس شکل دقیق پاسخ‌های استریم، `usage`، و ورودی/خروجی Whisper و Flux **تأییدنشده** است؛ اگر چیزی نخواند، همین‌جا معلوم می‌شود.
۴. یک پیام به AMIN AI بفرستید و ببینید جواب کلمه‌به‌کلمه می‌آید.
۵. **CPU:** داشبورد Cloudflare ← Workers & Pages ← `amin-chat` ← Metrics ← CPU time (p99) و Errors (وضعیت «Exceeded CPU Time Limits» نباید دیده شود). ثبت‌نام و ورود سنگین‌ترین درخواست‌ها هستند.

## به‌روزرسانی

با GitHub Actions: دوباره «Deploy to Cloudflare» را اجرا کنید. از رایانه:

```bash
git pull && npm ci && npm run deploy
```

مهاجرت‌ها فقط **رو به جلو** هستند (بدون برگشت). پیش از به‌روزرسانی‌ای که مهاجرت جدید دارد، از پایگاه داده نسخهٔ پشتیبان بگیرید:
`cd apps/api && npx wrangler d1 export amin-chat-db --remote --output ../../backup.sql`. (Cloudflare امکان بازگردانی به یک زمان قبلی هم دارد: «D1 Time Travel».) برگرداندن کد: `npx wrangler rollback` در `apps/api`.

## چرا دکمهٔ «Deploy to Cloudflare» یک‌کلیکی نیست؟

مستندات Cloudflare می‌گوید این دکمه monorepo را کامل پشتیبانی نمی‌کند: اگر آدرس به یک زیرپوشه اشاره کند، برنامه باید **با همهٔ وابستگی‌هایش** درون همان زیرپوشه باشد، وگرنه build شکست می‌خورد. این پروژه workspace است (`apps/api` به `packages/shared` و ساخت `apps/web` نیاز دارد)، پس دکمه‌ای نگذاشتم که بدانم خراب می‌شود. راه الف همان راحتی را با پایداری بیشتر می‌دهد.

```bash
npm run dev:api            # Worker + D1 + R2 + DO محلی روی ‎:8787، با Workers AI واقعی (نیاز به: npx wrangler login؛ این فراخوانی‌ها از سهمیهٔ حساب شما مصرف می‌شوند)
npm run dev:api:offline    # بدون اتصال به Cloudflare؛ هر قابلیت هوش مصنوعی خطای AI_NOT_CONNECTED می‌دهد (چیزی ساختگی تولید نمی‌شود)
```

## عیب‌یابی

| نشانه | علت و راه‌حل |
|---|---|
| «Could not ask Cloudflare which databases exist» | توکن غلط/منقضی است، `CLOUDFLARE_ACCOUNT_ID` درست نیست، یا توکن یکی از چهار ردیف مرحلهٔ ۳ را ندارد (بیشتر **D1: Edit**). هیچ‌چیز ساخته یا منتشر نشده است |
| Preflight: «! workers.dev address … no workers.dev address yet» | فقط هشدار: مرحلهٔ «Prepare the account» نشانی را ثبت می‌کند و می‌گوید کدام. اگر آن مرحله شکست خورد («none of the names tried was accepted» یا «could not register»)، یک بار خودتان در داشبورد ← Workers & Pages یک نام انتخاب کنید ([لینک مستقیم](https://dash.cloudflare.com/?to=/:account/workers/onboarding)) و دوباره اجرا کنید (برای «could not register» ردیف **Workers Scripts: Edit** توکن را هم ببینید) |
| در اجرا: «File storage is OFF» / «R2 is not switched on» (کد ۱۰۰۴۲) | R2 در حساب روشن نیست، پس سرویس بدون ذخیرهٔ فایل بالا آمد (ارسال فایل و عکس خاموش، بقیه کار می‌کند). برای افزودن: R2 را روشن کنید (روش پرداخت می‌خواهد) و دوباره deploy کنید |
| خطای دسترسی R2 («R2 cannot be used with this token») | توکن **Workers R2 Storage: Edit** ندارد (قالب Edit Cloudflare Workers دارد) |
| خطای ۱۱۰۲ / «Worker exceeded resource limits» | سقف ۱۰ میلی‌ثانیه CPU در پلن رایگان. هنگام ورود/ثبت‌نام: `PASSWORD_HASH_ITERATIONS` را کمتر کنید (حداقل ۱۰٬۰۰۰؛ پیش‌فرض این مخزن ۲۰٬۰۰۰). هنگام پاسخ‌های بلند هوش مصنوعی، یا اگر کم‌کردن کمک نکرد: به Workers Paid بروید |
| خطای ۱۰۲۷ | سقف ۱۰۰٬۰۰۰ درخواست در روز در پلن رایگان |
| `AI_NOT_CONNECTED` | نه بایندینگ `AI` هست و نه `GROQ_API_KEY` (حالت offline، یا wrangler.jsonc دست‌کاری شده) |
| مدل «در دسترس نیست» با دلیل `check_failed` یا `unverified` | یک مدل خطا داده (۲۰ دقیقه کنار می‌رود) یا هنوز بررسی نشده؛ دکمهٔ بررسی را بزنید. اگر همیشه شکست می‌خورد، به `npm run verify:ai` نگاه کنید |
