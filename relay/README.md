# رلهٔ AMIN CHAT (relay)

یک پروکسیِ معکوسِ کوچک و **بدون هیچ وابستگی** (فقط Node.js ‎20 به بالا) که ترافیک AMIN CHAT را به Worker شما می‌رساند.
وقتی آدرس Worker روی اینترنت بعضی کاربران (مثلاً در ایران) کند یا مسدود است، آن‌ها می‌توانند از طریق آدرسِ رله وصل شوند.
رله **همه چیز** را عبور می‌دهد: خودِ برنامهٔ وب، API و اتصال زنده (WebSocket). یعنی باز کردن آدرس رله در مرورگر، کل برنامه را می‌دهد.

> کد و رفتار دقیق: [`relay.mjs`](relay.mjs) · آزمون‌ها: [`relay.test.mjs`](relay.test.mjs) · تصویر کلی و محدودیت‌ها: [`../docs/connectivity.md`](../docs/connectivity.md)

## رله چه کاری **نمی‌کند** (و باید بدانید)

- **جادو نیست.** اگر مشکل فقط این است که آدرس‌ها و IPهای Cloudflare برای کاربر کند/مسدود است، رله کمک می‌کند. اگر کل اینترنت بین‌الملل قطع باشد، یا خودِ سرور رله از ایران قابل دسترسی نباشد، هیچ رله‌ای کمک نمی‌کند.
- **VPN نیست** و ترافیک دیگر برنامه‌ها را عبور نمی‌دهد؛ فقط به `UPSTREAM` وصل می‌شود (پروکسیِ باز نیست؛ درخواستِ `CONNECT` و آدرسِ کامل را رد می‌کند).
- **اپراتورِ رله می‌تواند محتوای چت‌های غیر E2EE را ببیند** (مثل هر پروکسی‌ای که TLS را تمام می‌کند). چت‌های رمزنگاریِ سرتاسری (E2EE) محافظت‌شده می‌مانند. فقط رله‌ای را بالا بیاورید یا به آن اعتماد کنید که خودتان آن را اجرا می‌کنید.
- رله هیچ آدرس IP و هیچ query string ای را لاگ نمی‌کند (توکن‌ها در query می‌آیند).

## راه‌اندازی سریع

شما به یک سرور با Node.js ‎20+ و یک نام دامنه که به آن اشاره کند نیاز دارید. سرور را جایی بگیرید که **از شبکهٔ کاربران قابل دسترسی** باشد
(این را باید از خودِ آن شبکه آزمایش کنید؛ وضعیت فیلترینگ مدام عوض می‌شود).

### ۱) یک رمز مشترک بسازید

رله باید به Worker بگوید «آدرسِ واقعیِ کاربر این است». بدون این، همهٔ کاربران در نگاه Worker «یک نفر» (خودِ رله) هستند و سقف‌های نرخ مشترک می‌شوند.

```bash
openssl rand -hex 24                        # یک رشتهٔ تصادفی؛ همان را در دو جا بگذارید
cd apps/api && npx wrangler secret put RELAY_SECRET     # یک بار روی Cloudflare (مقدار را بچسبانید)
```

### ۲) رله را اجرا کنید

```bash
UPSTREAM=https://amin-chat.your-subdomain.workers.dev \
RELAY_SECRET=همان-رشته \
TRUST_PROXY=1 PORT=8080 HOST=127.0.0.1 \
node relay/relay.mjs
```

اگر `UPSTREAM` یا یک مقدارِ دیگر اشتباه باشد، رله **همهٔ** مشکلات را یک‌جا فهرست می‌کند و بالا نمی‌آید (کد خروج ۲).
از ریشهٔ مخزن هم می‌توانید `npm run relay` را بزنید.

### ۳) HTTPS جلوی آن بگذارید

مرورگرها و برنامهٔ اندروید فقط آدرس **https** را می‌پذیرند. یکی از این سه راه:

| راه | فایل نمونه | نکته |
|---|---|---|
| **Caddy + Docker** (ساده‌ترین؛ گواهی را خودش می‌گیرد) | [`compose.example.yaml`](compose.example.yaml) + [`Caddyfile.example`](Caddyfile.example) | `docker compose -f compose.example.yaml up -d --build` |
| **nginx** | [`nginx.example.conf`](nginx.example.conf) | `Upgrade`/`Connection` برای WebSocket و `proxy_buffering off` برای پاسخ‌های جاری ضروری است |
| **خودِ رله TLS بدهد** | `TLS_CERT_FILE` و `TLS_KEY_FILE` | هر دو فایل PEM؛ پورت ۴۴۳ نیاز به `CAP_NET_BIND_SERVICE` دارد |

برای اجرای دائمی: [`Dockerfile`](Dockerfile) یا [`amin-relay.service`](amin-relay.service) (systemd، با سخت‌سازی).

> فایل‌های نمونهٔ Docker، Caddy، nginx و systemd در محیطی که این کد نوشته شد اجرا نشده‌اند (فقط Node داشت). خودِ `relay.mjs` با آزمون‌های خودکار
> و با Worker واقعی (workerd) و مرورگر واقعی آزمایش شده است. پیش از استفاده روی سرور، `nginx -t` یا `systemd-analyze verify` را بزنید.

### ۴) بررسی

```bash
curl https://relay.example.com/__relay/health          # {"ok":true,"relay":true}  ← خودِ رله زنده است
curl https://relay.example.com/api/health              # باید همان پاسخ Worker باشد: "service":"amin-chat"
```

اگر دومی خطا داد: `UPSTREAM` را بررسی کنید و اینکه خودِ سرور رله به آن دسترسی دارد (`curl $UPSTREAM/api/health` روی همان سرور).

### ۵) آدرس رله را به برنامه‌ها بدهید

سه راه (از خودکار به دستی):

1. **Worker آدرس را اعلام کند**: متغیر `PUBLIC_ENDPOINTS` در `apps/api/wrangler.jsonc` را برابر آدرس(ها) بگذارید (با کاما جدا) و دوباره deploy کنید. هر برنامه‌ای که **یک بار** به Worker وصل شده باشد، رله را یاد می‌گیرد و هنگام قطع شدنِ آدرس اصلی خودش به آن می‌رود. این آدرس‌ها به‌طور خودکار برای CORS هم معتبر می‌شوند.
2. **داخل برنامه ساخته شود** (برای نصب‌های تازه‌ای که هنوز هیچ‌وقت به سرور نرسیده‌اند): هنگام build، `VITE_API_BASES=https://relay.example.com` را بدهید ([`../apps/web/.env.example`](../apps/web/.env.example)؛ برای اندروید: [`../docs/android.md`](../docs/android.md)).
3. **کاربر خودش بزند**: تنظیمات ← اتصال ← «نشانی تازه».

## همهٔ تنظیمات (متغیرهای محیطی)

فقط `UPSTREAM` الزامی است. نمونه: [`.env.example`](.env.example).

| متغیر | پیش‌فرض | معنی |
|---|---|---|
| `UPSTREAM` | — (الزامی) | آدرس Worker شما، فقط origin (بدون مسیر). `http://` فقط برای loopback، یا با `ALLOW_INSECURE_UPSTREAM=1` در شبکهٔ خصوصی |
| `RELAY_SECRET` | خالی | همان مقدارِ secret در Worker؛ حداقل ۱۶ نویسه. بدون آن هشدار می‌دهد و سقف‌های نرخ مشترک می‌شوند |
| `TRUST_PROXY` | `0` | `1` وقتی nginx/Caddy/load balancer **خودتان** جلوی رله است و `X-Forwarded-For` را می‌گذارد (راست‌ترین مقدار خوانده می‌شود) |
| `PORT` / `HOST` | `8080` / `0.0.0.0` | کجا گوش بدهد |
| `TLS_CERT_FILE` / `TLS_KEY_FILE` | — | HTTPS مستقیم؛ هر دو با هم |
| `MAX_BODY_MB` | `64` | بزرگ‌ترین بدنهٔ درخواست (آپلود فایل). باید ≥ سقف فایل برنامه (۲۵ مگابایت) و با `client_max_body_size` در nginx یکی باشد |
| `CONNECT_TIMEOUT_MS` | `10000` | مهلت وصل شدن به Worker |
| `UPSTREAM_IDLE_TIMEOUT_MS` | `120000` | مهلت سکوتِ Worker (پاسخ جاری بین توکن‌ها سکوت کوتاه دارد) |
| `WS_LINGER_MS` | `10000` | بعد از بسته شدن یک سمتِ WebSocket، چه مدت سمت دیگر فرصت بسته شدن دارد |
| `REWRITE_WS_ORIGIN` | `1` | برای WebSocket، `Origin` را برابر آدرس Worker می‌کند (احراز هویتِ WebSocket با بلیت یک‌بارمصرف است، نه کوکی) |
| `LOG` | `1` | لاگ بدون آدرس و query |

## امنیت (خلاصه)

- هدرهایی که کاربر می‌تواند جعل کند (`X-Forwarded-For`، `X-Real-IP`، `Forwarded`، `X-Relay-Secret` و …) و کوکی‌ها حذف می‌شوند؛ فقط خودِ رله آن‌ها را می‌گذارد.
- `Set-Cookie` از پاسخ حذف می‌شود؛ هیچ پاسخی کش نمی‌شود؛ `X-Request-Id` و هدرهای CORS دست‌نخورده می‌گذرند (برنامه از `X-Request-Id` می‌فهمد پاسخ از سرور خودش است نه از یک صفحهٔ فیلترینگ).
- `RELAY_SECRET` را در گیت نگذارید. فایل `.env` در `.gitignore` است؛ فقط `.env.example` ثبت می‌شود.

## آزمون

```bash
npm run test:scripts        # آزمون‌های رله + اسکریپت‌ها
```

آزمون‌ها رله را در برابر یک سرور ساختگی روی پورت محلی (به‌جای Worker) بالا می‌آورند و بررسی می‌کنند: عبور HTTP و WebSocket (دست‌دادن، پیام در دو جهت، بسته شدن)،
جریان بدون بافر، حذف هدرهای جعلی و کوکی‌ها، امضای آدرس کاربر، رد `CONNECT` و آدرس کامل، سقف بدنه (۴۱۳)، خطای ۵۰۲ (Worker در دسترس نیست) و ۵۰۴ (پاسخ نمی‌دهد)
که عمداً `X-Request-Id` ندارند تا برنامه بفهمد از Worker نیامده‌اند، ننوشتن query در لاگ، HTTPS مستقیم (با `openssl` موجود) و تنظیمات نامعتبر.
رفتار با Worker واقعی (workerd) و مرورگر واقعی جداگانه دستی آزمایش شد؛ آن اسکریپت‌ها در مخزن نیستند.
